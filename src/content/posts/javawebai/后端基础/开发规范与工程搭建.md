<section><h1 id="开发规范与工程搭建">开发规范与工程搭建</h1><section><h2 id="定义">定义</h2><p>在 Tlias 智能学习辅助系统的实战开发中，首先需要建立统一的开发规范并完成基础工程搭建。这包括前后端分离开发模式、RESTful API 风格约定、接口测试工具的使用，以及 SpringBoot 工程的基础结构搭建。</p></section><section><h2 id="开发规范">开发规范</h2><section><h3 id="前后端分离开发">前后端分离开发</h3><p>企业项目开发主要有两种模式：前后台混合开发和前后台分离开发。</p><p>前后台混合开发的缺点：</p><ul>
<li>沟通成本高：后台发现前端问题需找前端修改，再交回后台</li>
<li>分工不明确：后台开发需同时写前端代码</li>
<li>不便管理：所有代码在一个工程中</li>
<li>难以维护：前端更新需要整个工程重新打包部署</li>
</ul><p><strong>前后台分离开发</strong>将工程分为前端工程和后端工程，前端交给专业前端人员，后端交给专业后端人员，双方通过<strong>接口文档</strong>约定数据格式。</p><p></p><center><figure><img src="/media/1fc03eb7cd25.png" alt=""><figcaption>前后端分离开发</figcaption></figure></center><p></p><p>后端开发功能的具体流程：</p><p></p><center><figure><img src="/media/7e0bba4d21f6.png" alt=""><figcaption>后端开发流程</figcaption></figure></center><p></p><ol>
<li>需求分析：阅读需求文档，分析需求</li>
<li>接口定义：查询接口文档中关于需求的接口定义（地址、参数、响应数据类型等）</li>
<li>前后台并行开发：各自按照接口文档进行开发</li>
<li>测试：各自按照接口文档进行测试</li>
<li>前后端联调测试：前端工程请求后端工程，测试功能</li>
</ol></section><section><h3 id="restful-风格">RESTful 风格</h3><p>REST（Representational State Transfer），表述性状态转换，是一种软件架构风格。</p><p>传统 URL 风格：</p><ul>
<li><code>http://localhost:8080/user/getById?id=1</code> — GET：查询 id 为 1 的用户</li>
<li><code>http://localhost:8080/user/saveUser</code> — POST：新增用户</li>
<li><code>http://localhost:8080/user/updateUser</code> — POST：修改用户</li>
<li><code>http://localhost:8080/user/deleteUser?id=1</code> — GET：删除 id 为 1 的用户</li>
</ul><p>传统 URL 将资源访问行为暴露在外，且不同开发人员命名习惯各异（<code>getById</code>、<code>selectById</code>、<code>queryById</code>），难以统一维护。</p><p>基于 REST 风格 URL：</p><ul>
<li><code>http://localhost:8080/users/1</code> — GET：查询 id 为 1 的用户</li>
<li><code>http://localhost:8080/users</code> — POST：新增用户</li>
<li><code>http://localhost:8080/users</code> — PUT：修改用户</li>
<li><code>http://localhost:8080/users/1</code> — DELETE：删除 id 为 1 的用户</li>
</ul><p>核心原则：<strong>通过 URL 定位要操作的资源，通过 HTTP 动词（请求方式）来描述具体的操作。</strong></p>

<table><thead><tr><th>请求方式</th><th>操作</th></tr></thead><tbody><tr><td>GET</td><td>查询</td></tr><tr><td>POST</td><td>新增</td></tr><tr><td>PUT</td><td>修改</td></tr><tr><td>DELETE</td><td>删除</td></tr></tbody></table><p>注意事项：</p><ul>
<li>REST 是风格、约定方式，约定不是规定，可以打破</li>
<li>描述模块功能通常使用复数（加 s），表示此类资源而非单个资源。如：users、emps、books</li>
</ul></section><section><h3 id="apifox-工具">Apifox 工具</h3><p>Apifox 是一款集成了 API 文档、API 调试、API Mock、API 测试的一体化协作平台。</p><ul>
<li>作用：接口文档管理、接口请求测试、Mock 服务</li>
<li>官网：<a href="https://apifox.com/" target="_blank" rel="noopener noreferrer">https://apifox.com/</a></li>
</ul><p>在前后端并行开发时，由于浏览器只能发起 GET 请求，无法直接测试 POST、DELETE、PUT 等接口，需要借助 Apifox 等接口测试工具完成接口测试。</p></section></section><section><h2 id="工程搭建">工程搭建</h2><section><h3 id="创建-springboot-工程">创建 SpringBoot
