<section><h2 id="前言">前言</h2><p>给自己的图床开了随机图功能之后，对着官方文档研究半天，结果发现真正用起来就几行代码的事。官方文档写得太”文档化”了，这篇用大白话把随机图 API 讲明白，顺便记下我实测踩过的三个坑。</p></section>
<section><h2 id="随机图-api-是什么">随机图 API 是什么</h2><p>一句话：<strong>一个网址，每打开一次，就从你图床的某个文件夹里随机抽一张图返回给你。</strong></p><p>你可以把它当”随机壁纸接口”用，也可以给网站当随机背景、给文章配随机封面。</p></section>
<section><h2 id="前提先把功能开起来">前提：先把功能开起来</h2><p>两个步骤：</p><ol>
<li>进入图床管理后台 → 系统设置 → 找到「随机图」开关，打开</li>
<li>配置一个<strong>允许随机访问的目录</strong>，比如 <code>/blog/随机封面图</code>（填这个目录名，带不带开头的斜杠都行）</li>
</ol><p>第二步很重要：不开目录，或者请求时乱指定目录，都会报 <code>Directory not allowed</code> 错误。</p></section>

<section><h2 id="我踩过的三个坑">我踩过的三个坑</h2><section><h3 id="坑一不带-dir-报-directory-not-allowed">坑一：不带 <code>dir</code> 报 <code>Directory not allowed</code></h3><p>图床开了目录白名单之后，<strong>每次请求必须显式带上 <code>dir</code></strong>，且目录必须在后台配置的允许范围里。别指望”不传就默认整个图床随机”——会直接报错。</p></section><section><h3 id="坑二上传的图片随机不到">坑二：上传的图片”随机不到”</h3><p>实测发现：如果上传文件时没带正确的文件类型（比如写脚本上传时 <code>Blob</code> 没设置 MIME 类型），图床会把文件记录成 <code>application/octet-stream</code>。文件本身没问题、直链也能访问，但<strong>随机图 API 按”图片”筛选时直接跳过它</strong>，表现就是：文件夹里明明有几十张图，随机接口却返回空。</p><p>排查方法：管理后台看该文件的类型是不是显示成 <code>application/octet-stream</code>。修复方法：删除后重新上传，上传时确保带正确类型（webp/png/jpg 等）。</p></section><section><h3 id="坑三多个地方用同一个-url显示的会是同一张图">坑三：多个地方用同一个 URL，显示的会是同一张图</h3><p>随机接口本身每次都会随机，但<strong>浏览器会缓存</strong>：如果页面上十几个位置都写同一个 <code>/random?...</code> 地址，浏览器只会请求一次，然后全部位置显示同一张图。</p><p>解法：给每个使用位置加一个不同的参数，让 URL 不一样即可（图床不认识这个参数也没关系，它只是让浏览器认为”这是不同的网址”）：</p><div class="expressive-code"><figure class="frame"><figcaption class="header"></figcaption><pre data-language="plaintext"><code><div class="ec-line"><div class="gutter"><div class="ln" aria-hidden="true">1</div></div><div class="code"><span style="--0:#abb2bf;--1:#383a42">../../../_external/img.tsh520.cn/random.bin</span></div></div></code></pre><div class="copy"><div aria-live="polite"></div><button title="Copy to clipboard" data-copied="Copied!" data-code="/_external/img.tsh520.cn/random.bin"><div></div></button></div></figure></div><p><code>v</code> 换成每篇文章独有的编号（文章 ID、slug、序号都行），这样每篇文章各请求一次、各拿到一张，同篇文章刷新后也不会变（URL 固定）。</p></section><section><h3 id="补充提醒加载速度">补充提醒：加载速度</h3><p>随机接口每次请求都要实时查数据库，比访问一张固定图片慢一些。<strong>不适合放首屏关键位置</strong>（比如首页 Hero、导航 Logo），适合做背景、封面这种”锦上添花”的场景。追求极致速度的话，还是用固定图片直链走 CDN 缓存。</p></section></section>
<section><h2 id="总结">总结</h2><ul>
<li>开随机图 = 后台开开关 + 配一个允许目录</li>
<li>用随机图 = 一个带 <code>dir</code> 的网址，加 <code>type=img</code> 直接出图</li>
<li>三个坑：必须带 <code>dir</code>、上传要带正确 MIME 类型、多个位置要用 <code>&#x26;v=xxx</code> 区分开</li>
</ul><p>这套东西配置一次，之后所有需要”随机图片”的地方都能一键复用。</p></section>
