<section><h1 id="背景为什么我懒得更新博客">背景：为什么我懒得更新博客</h1><p>之前写博客（<a href="/posts/技术分享/记录博客文件的最佳存储方式/">Firefly Astro 静态站</a>）有个很烦的问题：<strong>想发一条动态，流程太长</strong>。</p><ul>
<li>❌ 得开电脑、开编辑器、改 markdown 文件</li>
<li>❌ 图片要先传到图床上，手动拿链接</li>
<li>❌ 足迹要填省份、城市，还得查经纬度</li>
<li>❌ 提交、构建、部署，一步都不能少</li>
</ul><p>灵感是即时的，流程是繁琐的。很多时候想想这个流程，算了不发了。</p><p>后来我折腾出了一个方案：<strong>用 AstrBot 把博客的后台搬进微信</strong>。现在发动态就像聊天一样简单。</p><hr></section>

<section><h1 id="方便在哪">方便在哪</h1><p>✅ <strong>手机随手发</strong>：灵感来了直接发，不用开电脑<br>
✅ <strong>图片自动上链</strong>：微信收图 → 自动传图床 → 链接自动写进文章，不用手动传<br>
✅ <strong>足迹坐标自动化</strong>：高德地理编码，输入地名就有经纬度<br>
✅ <strong>标签自定义</strong>：<code>#日常</code> <code>#2026</code> 随手打，自动合并默认标签<br>
✅ <strong>构建部署全自动</strong>：GitHub 提交 → Actions 构建 → 页面自动上线<br>
✅ <strong>增量发布</strong>：图片失败/坐标失败都会中止，绝不产生半成品提交</p><hr></section>
<section><h1 id="这套方案踩过的坑">这套方案踩过的坑</h1><p>方案看着简单，做起来还是有不少坑的，都记下来了：</p><ul>
<li>⚠️ <strong>微信的图片是临时文件</strong>：个人微信适配器收图后存在 <code>data/temp</code>，消息处理完就被清理。所以插件必须在收到图片的瞬间就读进内存，发布时直接用。</li>
<li>⚠️ <strong>YAML 引号会炸构建</strong>：<code>published</code> 加引号会变成字符串，Astro 的 schema 直接报错；纯数字标签（<code>#2026</code>）也必须加引号，否则被解析成数字。格式必须和现有数据一字不差。</li>
<li>⚠️ <strong>监听器会抢占对话</strong>：拦截所有消息的监听器如果乱回复，会把机器人的正常聊天抢走。非白名单用户必须静默忽略，只放行博客相关命令。</li>
<li>⚠️ <strong>图床接口要看文档</strong>：上传接口、认证方式（Bearer Token）、响应格式（数组），都得对着文档来，不能凭猜。</li>
</ul><hr></section>
<section><h1 id="结语">结语</h1><p>博客的本质是记录。记录的门槛越低，记录得越多。</p><p>现在这套方案让我做到了「<strong>想到什么就发什么</strong>」：路边看到一只猫，拍张照发过去，一条动态上线；到了一个地方，随手一条消息，足迹就记下了——连经纬度都不用我操心。</p><p>技术栈一句话总结：<strong>AstrBot（微信入口）+ BlogWriter 插件（命令解析与生成）+ CloudFlare-ImgBed（图床）+ 高德（坐标）+ GitHub API（提交）+ EdgeOne Pages（部署）</strong>，全链路零服务器成本（复用现有部署），一次搭好，永久受益。</p><p>如果你也是静态博客，也想让更新变得像聊天一样简单，这个思路值得抄。</p></section>
