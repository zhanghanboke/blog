<section><h1 id="泛型">泛型</h1><section><h2 id="一-泛型的引入与好处">一、 泛型的引入与好处</h2><section><h3 id="11-传统方法的问题">1.1 传统方法的问题</h3><p>在集合中，使用传统方法（不使用泛型）存在两个主要问题：</p><ol>
<li>​<strong>类型不安全</strong>：不能对加入到集合中的数据类型进行约束，可以添加任意类型的对象。</li>
<li>​<strong>效率低</strong>​：遍历时，需要进行频繁的类型转换（Object -> 具体类型），数据量大时影响效率。</li>
</ol></section><section><h3 id="12-泛型的好处">1.2 泛型的好处</h3><p>使用泛型可以解决上述问题：</p><ol>
<li>
<p>​<strong>类型安全</strong>：在编译时检查添加元素的类型，不符合则报错，提高了安全性。</p>
</li>
<li>
<p>​<strong>提高效率</strong>：减少了遍历时不必要的类型转换次数。</p>
<ul>
<li>不使用泛型：Dog -> Object (存入) -> Dog (取出，需强转)</li>
<li>使用泛型：Dog -> Dog (存入) -> Dog (取出，无需强转)</li>
</ul>
</li>
<li>
<p>​<strong>消除警告</strong>：代码更加简洁、健壮，不再有编译警告。</p>
</li>
</ol></section></section><section><h2 id="二-泛型介绍">二、 泛型介绍</h2><section><h3 id="21-基本概念">2.1 基本概念</h3><ul>
<li>​<strong>泛型</strong>​：又称​<strong>参数化类型</strong>，是 JDK 5.0 引入的新特性。</li>
<li>​<strong>核心思想</strong>：在类声明或实例化时，通过一个标识符来指定操作的数据类型。</li>
<li>​<strong>作用</strong>：可以在类声明时，用一个标识符表示类中某个属性的类型、某个方法的返回值类型或参数类型。</li>
<li>​<strong>优点</strong>：保证如果程序在编译时没有发出警告，运行时就不会产生 ClassCastException 异常。</li>
</ul></section></section><section><h2 id="三-泛型语法与使用">三、 泛型语法与使用</h2><section><h3 id="31-泛型的声明与实例化">3.1 泛型的声明与实例化</h3><ul>

<li>​<strong>实例化</strong>​：在创建对象时，在尖括号 &#x3C;> 中指定具体的类型。</li>

<li>​<strong>基本语法</strong>​：class 类名&#x3C;T, R…> { … }</li>
</ul><p></p><center><figure><img alt="" loading="lazy" decoding="async" width="716" height="308" src="/media/0686bc56d644.webp" srcset=""><figcaption>|500</figcaption></figure></center><p></p><ul>
<li>
<p>​<strong>注意细节</strong>：</p>
<ol>
<li>普通成员（属性、方法）可以使用泛型。</li>
<li><strong>不能初始化</strong>使用泛型的数组（因为 new 时无法确定 T 的具体类型）。</li>
<li>​<strong>静态成员</strong>（属性、方法）中不能使用类的泛型（因为静态成员在类加载时初始化，而泛型类型在创建对象时才确定）。</li>
<li>泛型类的类型，是在<strong>创建对象时确定</strong>的。</li>
<li>如果在创建对象时没有指定类型，则默认为 Object。</li>
</ol>
</li>
</ul></section><section><h3 id="42-自定义泛型接口">4.2 自定义泛型接口</h3><ul>
<li>
<p>​<strong>基本语法</strong>​：interface 接口名&#x3C;T, R…> { … }</p>
</li>
<li>
<p>​<strong>注意细节</strong>：</p>
<ol>
<li>接口中，静态成员也不能使用泛型（同泛型类）。</li>
<li>泛型接口的类型，在<strong>继承接口</strong>或<strong>实现接口</strong>时确定。</li>
<li>没有指定类型，默认为 Object。</li>
</ol>
</li>
</ul></section><section><h3 id="43-自定义泛型方法">4.3 自定义泛型方法</h3><ul>
<li>
<p>​<strong>基本语法</strong>​：修饰符 &#x3C;T, R…> 返回类型 方法名(参数列表) { … }</p>
</li>
<li>
<p>​<strong>注意细节</strong>：</p>
<ol>
<li>泛型方法可以定义在普通类中，也可以定义在泛型类中。</li>
<li>当泛型方法被调用时，类型会确定。</li>
<li>public void eat(E e) {} 这样的方法，其泛型 E 依赖于类定义的泛型，不是泛型方法。</li>
<li>public &#x3C;T> void fly(T t) {} 这样的方法，其泛型 T 独立于类，是泛型方法。</li>
</ol>
</li>
</ul></section></section><section><h2 id="五-泛型的继承和通配符">五、 泛型的继承和通配符</h2><section><h3 id="51-泛型没有继承性">5.1 泛型没有继承性</h3><ul>
<li>虽然 String 是 Object 的子类，但 List&#x3C;String> 并不是 List&#x3C;Object> 的子类。它们是并列关系，没有继承关系。</li>
</ul></section><section><h3 id="52-泛型通配符">5.2 泛型通配符</h3><p>为了表示泛型之间的某种关系，引入了通配符 ?。</p><ol>
<li>
<p><strong>&#x3C;?>：无界通配符</strong></p>
<ul>
<li>表示可以接受<strong>任意</strong>的泛型类型。</li>
<li>List&#x3C;?> 是 List&#x3C;String>, List&#x3C;Object> 等各种泛型 List 的父类。</li>
<li>​<strong>注意</strong>​：不能向 List&#x3C;?> 中添加除 null 以外的任何元素（因为类型不确定），但可以读取，读取出的类型是 Object。</li>
</ul>
</li>
<li>
<p><strong>&#x3C;? extends A>：上界通配符</strong></p>
<ul>
<li>表示可以接受 ​<strong>A 类以及 A 类的子类</strong>（不限于直接子类）。</li>
<li>规定了泛型的​<strong>上限</strong>。</li>
<li>同样，不能向 List&#x3C;? extends A> 中添加除 null 以外的任何元素（因为无法确定具体是哪个子类），但可以读取，读取出的类型是 A。</li>
</ul>
</li>
<li>
<p><strong>&#x3C;? super A>：下界通配符</strong></p>
<ul>
<li>表示可以接受 ​<strong>A 类以及 A 类的父类</strong>（不限于直接父类）。</li>
<li>规定了泛型的​<strong>下限</strong>。</li>
<li>可以向 List&#x3C;? super A> 中添加 A 及其子类对象（因为父类引用可以指向子类对象）。</li>
<li>读取时，返回的类型是 Object。</li>
</ul>
</li>
</ol></section></section><section><h2 id="六-junit-单元测试补充">六、 JUnit 单元测试（补充）</h2><section><h3 id="61-为什么需要-junit">6.1 为什么需要 JUnit</h3><ul>
<li>传统测试需要将代码写入 main 方法，测试多个功能时需要来回注销、切换，非常麻烦。</li>
<li>JUnit 可以直接运行一个方法进行测试，并给出相关信息，方便快捷。</li>
</ul></section><section><h3 id="62-基本介绍">6.2 基本介绍</h3><ul>
<li>JUnit 是一个 Java 语言的单元测试框架。</li>
<li>多数 Java 开发环境（如 IDEA）都已集成 JUnit 作为单元测试工具。</li>
</ul></section><section><h3 id="63-使用步骤简述">6.3 使用步骤（简述）</h3><ol>
<li>在需要测试的类中，导入 JUnit 相关包（通常由 IDE 自动完成）。</li>
<li>在需要测试的方法上添加 @Test 注解。</li>
<li>在方法体内编写测试代码。</li>
<li>右键点击方法名或类名，选择 Run ‘方法名()’ 或 Run ‘类名’ 执行测试。</li>
</ol></section></section></section>
