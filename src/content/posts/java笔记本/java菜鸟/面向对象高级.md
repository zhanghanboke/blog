<section><h2 id="一类变量和类方法-static关键字">一、类变量和类方法 (static关键字)</h2><section><h3 id="1-类变量静态变量">1. 类变量（静态变量）</h3><ul>
<li>​提出问题​：如何统计所有对象共享的一个数据？（如：统计玩游戏的小孩总数）</li>
<li>​传统方法的局限​：在main方法中定义计数变量，不面向对象，访问麻烦。
​<img alt="" loading="lazy" decoding="async" width="641" height="271" src="/media/bce42241a8ee.webp" srcset=""></li>
<li>​解决方案​：使用​类变量​。
<ul>
<li>​定义语法​：访问修饰符 static 数据类型 变量名; (推荐)</li>
<li>​特点​：
<ol>
<li>被该类的​所有对象实例共享​。</li>
<li>在类加载时就初始化生成。</li>
<li>生命周期随类的加载而开始，随类的消亡而销毁。</li>
</ol>
</li>
<li>​访问方式​：
<ul>
<li>类名.类变量名 (推荐)</li>
<li>对象名.类变量名</li>
</ul>
</li>
<li>​内存布局​：static变量是对象共享的（具体位置与JDK版本有关，可能在堆或方法区，共识是共享的）。</li>
</ul>
</li>
</ul></section><section><h3 id="2-类方法静态方法">2. 类方法（静态方法）</h3><ul>
<li>​定义语法​：访问修饰符 static 返回类型 方法名() { }</li>
<li>​调用方式​：类名.类方法名 或 对象名.类方法名。</li>
<li>​经典使用场景​：工具类方法（如Math、Arrays中的方法）。​当方法中不涉及任何和对象相关的成员时​，可设计为静态方法，提高效率。</li>
<li>​注意事项与细节​：
<ol>
<li>类方法和普通方法都随类加载而加载，结构信息存储在方法区。</li>
<li>类方法中无this参数​；普通方法中隐含着this参数​。</li>
<li>​核心口诀​：​静态方法只能访问静态成员（静态变量、静态方法）​。普通成员方法既可以访问非静态成员，也可以访问静态成员。</li>
<li>类方法中<strong>不能使用this和super</strong>关键字。</li>
<li>静态方法可以通过类名调用；普通方法必须通过对象名调用。</li>
</ol>
</li>
</ul></section></section>
<section><h2 id="二理解main方法语法">二、理解main方法语法</h2><ul>
<li>public static void main(String[] args) {}</li>
<li>​深入理解​：
<ol>
<li>main方法由Java虚拟机(JVM)调用。</li>
<li>public: JVM需要调用，访问权限必须公开。</li>
<li>static: JVM调用时不必创建对象。</li>
<li>void: 无返回值给JVM。</li>
<li>String[] args: 接收命令行参数。</li>
</ol>
</li>
<li>在main方法中的访问规则​：
<ol>
<li>可以直接访问本类的​静态成员​。</li>
<li>不能直接访问本类的​非静态成员​，必须创建对象后通过对象访问。</li>
</ol>
</li>
</ul></section>

<li>​基本语法​：</li>

<li>​使用细节与执行顺序（非常重要！）​：
<ol>

</ol>
</li>
</ul></section>
<section><h2 id="四单例设计模式">四、单例设计模式</h2><ul>
<li>​设计模式​：在大量实践中总结出的优选代码结构、编程风格和解决问题的思考方式。</li>
<li>​单例模式​：保证在整个软件系统中，对某个类​只能存在一个对象实例​，并提供一个获取该实例的全局访问点。</li>
<li>​实现步骤​：
<ol>
<li>构造器私有化（防止外部new）。</li>
<li>类的内部创建对象。</li>
<li>向外暴露一个公共的静态方法 (getInstance) 来获取该对象。</li>
</ol>
</li>
<li>​两种实现方式​：
<ul>
<li>​饿汉式​：类加载时就创建对象实例。
<ul>
<li>​优点​：线程安全（天然）。</li>
<li>​缺点​：可能造成资源浪费（如果实例一直未被使用）。</li>
</ul>
</li>
<li>​懒汉式​：使用时才创建对象实例。
<ul>
<li>​优点​：避免资源浪费。</li>
<li>​缺点​：存在线程安全问题（后续线程部分解决）。</li>
</ul>
</li>
</ul>
</li>
<li>​应用实例​：java.lang.Runtime 是经典的单例模式。</li>
</ul></section>
<section><h2 id="五final关键字">五、final关键字</h2><ul>
<li>​含义​：最终的。可以修饰类、属性、方法和局部变量。</li>
<li>​使用场景​：
<ol>
<li>​修饰类​：该类​不能被继承​（如String类）。</li>
<li>​修饰方法​：该方法​不能被重写/覆盖​。</li>
<li>​修饰属性​：该属性变为​常量​，值必须初始化且之后不能修改。</li>
<li>​修饰局部变量​：该局部变量值不能修改。</li>
</ol>
</li>
<li>​使用细节​：
<ol>
<li>final修饰的属性（常量）命名一般用XX_XX_XX（大写+下划线）。</li>
<li>final属性​必须赋初值​，赋值位置可选：
<ul>
<li>定义时。</li>
<li>在构造器中。</li>
<li>在代码块中。</li>
</ul>
</li>
<li>如果final修饰的属性是静态的，则初始化位置只能是：
<ul>
<li>定义时。</li>
<li>在静态代码块中。（​不能在构造器中​）</li>
</ul>
</li>
<li>final类不能继承，但可以实例化对象。</li>
<li>含有final方法的非final类，该方法可以被继承，但不能被重写。</li>
</ol>
</li>
</ul></section>
<section><h2 id="六抽象类">六、抽象类</h2><ul>
<li>​提出问题​：父类方法需要声明，但无法确定具体实现（如Animal的eat方法）。
​<img alt="" loading="lazy" decoding="async" width="576" height="266" src="/media/3dad4d096689.webp" srcset=""></li>
<li>​解决之道​：使用abstract关键字。
<ul>
<li>abstract修饰类 -> ​抽象类​。</li>
<li>abstract修饰方法 -> ​抽象方法​（没有方法体）。</li>
</ul>
</li>
<li>​介绍​：抽象类的价值更多在于​设计​，让子类继承并实现其抽象方法。是框架和设计模式中常用的知识点。</li>
<li>​注意事项与细节​：
<ol>
<li>​抽象类不能被实例化​。</li>
<li>抽象类不一定包含abstract方法​。但一旦包含abstract方法，该类必须声明为abstract。</li>
<li>abstract只能修饰类和方法，不能修饰属性和其他。</li>
<li>抽象类本质还是类，可以有任意成员（属性、方法、构造器、代码块等）。</li>
<li>如果一个类继承了抽象类，则它必须实现父类的所有抽象方法，除非它自己也声明为abstract类。</li>
<li>​抽象方法不能使用private、final和static修饰​，因为这些关键字与重写相违背。</li>
</ol>
</li>
</ul></section>
<section><h2 id="七抽象类最佳实践模板设计模式">七、抽象类最佳实践——模板设计模式</h2><ul>
<li>​介绍​：抽象类体现了一种模板模式设计，作为多个子类的通用模板。子类在抽象类基础上扩展，但总体上保留抽象类的行为方式。</li>
<li>​解决问题​：当功能内部一部分实现是确定的，一部分不确定时。将不确定的部分暴露为抽象方法，让子类实现。</li>
<li>​最佳实践案例​：统计不同任务执行的时间。
<ul>
<li>在抽象父类 (Template) 中，定义计算时间的通用方法 (calculateTime)。</li>
<li>将具体任务 (job) 声明为抽象方法，由子类实现。</li>
<li>这样既统一了计时逻辑，又保留了子类任务的灵活性。</li>
</ul>
</li>
</ul></section>

<li>多继承冲突
场景：类实现了两个接口，且这两个接口有同名的 default 方法。
结果：编译报错。
解决：实现类必须重写该方法，并使用 InterfaceName.super.methodName() 指定调用哪一个父接口的逻辑。
优先级规则：抽象方法 > 默认方法。如果一个是抽象方法，一个是默认方法，实现类必须实现抽象方法（默认方法自动失效）。</li>
<li>访问权限控制
​对外​：接口中的抽象方法和默认方法本质上都是 public​。</li>
<li>重写规则：实现类在重写接口方法时，必须使用 public​ 修饰符，不能降低访问权限（如改为 protected或private）。</li>
<li>函数式接口 (Functional Interface)
​定义​：只包含一个抽象方法的接口。
​用途​：Lambda 表达式的基础。</li>
<li>注解：推荐加上 @FunctionalInterface​，编译器会检查是否只有一个抽象方法（允许有多个 default/static 方法）。</li>
</ol></section><section><h3 id="最佳实践建议">最佳实践建议</h3><ol>
<li>​接口隔离​：保持接口小而专一，避免“胖接口”。</li>
<li>​向后兼容​：升级旧接口时，优先使用 default​ 方法添加新功能，避免破坏现有实现类。</li>
<li>​代码复用​：如果多个接口需要共享逻辑，优先考虑抽象类；如果必须用接口，利用 Java 9 的 private​ 方法在接口内部提取公共逻辑。</li>
<li>​常量管理​：虽然接口可以定义常量，但不要把接口当作纯粹的常量容器（Constant Interface 反模式），建议使用类或枚举来管理常量。</li>
</ol></section></section>
<section><h2 id="九内部类">九、内部类</h2><section><h3 id="1-局部内部类">1. 局部内部类</h3><ul>
<li>定义：定义在方法体、构造器或代码块内部。</li>
<li>特点：
<ol>
<li>可以直接访问外部类的所有成员（包含私有）。</li>
<li>不能使用访问修饰符（public/private）或 static​（地位如同局部变量），但可用final修饰。</li>
<li>作用域仅限当前代码块，外部不可见。</li>
<li>外部其他类不能访问局部内部类。</li>
<li>如果外部类和内部类成员重名，默认就近原则，访问外部类成员用外部类名.this.成员。</li>
<li>​访问局部变量限制​：只能访问 final​ 或 ​effectively final​（初始化后未修改）的局部变量。
<ul>
<li>原理：生命周期不一致（栈 vs 堆），Java 通过值复制实现闭包。</li>
</ul>
</li>
</ol>
</li>
<li>​适用场景​：逻辑仅在当前方法内使用，避免污染类结构。</li>
</ul></section><section><h3 id="2-匿名内部类极其重要">2. 匿名内部类（极其重要！）</h3><p>定义：没有类名的内部类，定义即实例化。
本质：同时是一个类、一个对象。
特点：</p><ul>
<li>本质是局部内部类的特例。</li>
<li>必须继承一个父类或实现一个接口。</li>
<li>不能定义构造函数（无名），不能定义静态成员。</li>
<li>​this​ 指向匿名类实例本身。

<li>定义：位于外部类内部，与成员变量同级，无 static​ 修饰。</li>
