<section><h1 id="使用-pagescms-给静态博客接入后台">使用 PagesCMS 给静态博客接入后台</h1><p>静态博客（Astro / Hexo / Hugo）最大的痛点就是<strong>没有后台</strong>：发一篇文章要么本地改文件再推送，要么自己写一套后台（还要管登录、安全、维护，成本不低）。</p><p>这篇文章介绍一个<strong>零代码、零依赖</strong>的方案——<a href="https://pagescms.org/" target="_blank" rel="noopener noreferrer">PagesCMS</a>：只需要在仓库里放一个 YAML 配置文件，就能获得可视化编辑后台，手机上也能发文章。</p><!-- 📷 插图 1：PagesCMS 后台界面截图
	图片放 images/ 目录，用 ![截图](images/xxx.png) 的格式替换本注释 --><section><h2 id="原理">原理</h2><p>PagesCMS 以 <strong>GitHub 仓库为唯一数据源</strong>，整个链路是：</p><ol>
<li>仓库根目录放一个 <code>.pages.yml</code>，声明你的内容模型（文章、友链、动态…）</li>
<li>在 PagesCMS 云界面（或自托管）里可视化编辑内容</li>
<li>它通过 GitHub API 把改动 <strong>commit 写回仓库</strong></li>
<li>部署平台（GitHub Pages / EdgeOne / Vercel / Cloudflare 等）检测到 push <strong>自动重建</strong></li>
</ol><p>CMS 本身不参与构建，也不关心你部署在哪——只要你的站点是”从 Git 仓库构建”的，它就能工作。</p><!-- 📷 插图 2：工作原理示意图（仓库 → CMS 编辑 → GitHub 写回 → 平台重建） --><p><strong>为什么适合静态博客</strong>：官方内置 Astro 博客模板，社区大量 Astro 用户在用；对已有的内容集合（如 <code>src/content/</code> 下的 md 文件）零改造即可接入。</p></section><section><h2 id="前置条件">前置条件</h2><ul>
<li>博客内容是 <strong>Git 仓库里的文件</strong>（这本来就是静态博客的常态）</li>
<li>部署平台与 GitHub 集成（push 自动触发构建）</li>
<li>项目使用标准的 frontmatter（YAML 头）格式</li>
</ul></section><section><h2 id="第一步编写-pagesyml">第一步：编写 <code>.pages.yml</code></h2><p>在仓库<strong>根目录</strong>新建 <code>.pages.yml</code>，核心结构：</p><div class="expressive-code"><div class="ec-collapse
