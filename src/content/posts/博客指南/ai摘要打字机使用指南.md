<p>博客为每篇文章详情页顶部配备了一个 AI 摘要打字机组件，读者打开文章时会以打字机动画形式逐字展示文章摘要，提升阅读体验。</p>
<section><h2 id="功能概览">功能概览</h2><ul>
<li>文章详情页顶部自动展示一段摘要</li>
<li>摘要以打字机动画逐字显示，标点处稍作停顿，模拟真人打字节奏</li>
<li>只在首次滚动到摘要区域时播放一次，不会重复触发</li>
<li>尊重用户系统设置：开启了「减少动态效果」的设备会直接静态显示全文</li>
<li>摘要内容优先读取你手动编写的 <code>description</code> 字段，没有时才由 AI 补全</li>
</ul></section>
<section><h2 id="摘要来源">摘要来源</h2><p>所有文章的摘要来源由 frontmatter 中的 <code>descriptionSource</code> 字段标记：</p>

<table><thead><tr><th>值</th><th>含义</th><th>页面显示</th></tr></thead><tbody><tr><td><code>manual</code></td><td>人工编写</td><td>📝 人工编写</td></tr><tr><td><code>ai</code></td><td>千问 AI 生成</td><td>🧠 AI 摘要</td></tr></tbody></table><p>你完全可以自己写 description 并标记 <code>descriptionSource: manual</code>，这样就不会被 AI 覆盖。</p></section>

<li>请求之间间隔 600ms，避免触发 API 限流</li>
</ul></section></section>
<section><h2 id="ai-生成的摘要是像人写的吗">AI 生成的摘要是「像人写的」吗？</h2><p>我们在补全脚本中内置了一套精心设计的提示词（Prompt），让千问知道：</p><ul>
<li>不要用「本文主要讲述了」「这篇文章介绍了」这种机械开头</li>
<li>不要堆砌概念、不要写成说明书提纲</li>
<li>要自然、口语化，像一个真实的博主在给读者做开场铺垫</li>
<li>技术文章保持清晰但别冷冰冰，生活感文章语气柔和一些</li>
<li>保留原作者的情绪和语气</li>
</ul><p>所以生成出来的摘要更像这样：</p><blockquote><p>折腾了两天终于把Nginx反代配通了，中间踩了三个莫名其妙的坑，趁热记下来免得下次再掉进去 😤</p></blockquote><p>而不是：</p><blockquote><p>本文主要介绍了Nginx反向代理的配置方法，包括常见的错误排查和解决方案。</p></blockquote></section>

<section><h2 id="注意事项">注意事项</h2><ol>
<li><strong>脚本不上传 GitHub</strong>：<code>scripts/fill-descriptions.ts</code> 已加入 <code>.gitignore</code>，因为它包含千问 API 密钥，确保不会泄露到公开仓库。</li>
<li><strong>只写 description 不写 content</strong>：脚本只修改 frontmatter 中的 <code>description</code> 和 <code>descriptionSource</code>，不会触碰文章正文内容。</li>
<li><strong>无描述不显示摘要</strong>：如果文章没有 <code>description</code> 且未运行过补全脚本，文章页面不会显示摘要区域，不影响正常页面渲染。</li>
<li><strong>千问模型选择</strong>：当前使用 <code>qwen-plus</code>（性价比之选），如有需要可切换为 <code>qwen-max</code>（质量更好）或 <code>qwen-turbo</code>（更快更便宜）。</li>
</ol></section>
